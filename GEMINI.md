# GEMINI.md

Инструкции и инженерные инварианты для AI-агента и разработчиков проекта **code-reviewer** — локального AI код-ревьюера с картой репозитория и графом зависимостей.

## Обзор проекта

`code-reviewer` выполняет анализ изменений (git diff) в контексте всего репозитория по двухпроходной схеме:

1. **`init` (локально, без вызовов LLM):** обход файлов с учётом `.gitignore`, извлечение символов, сигнатур, docstrings/комментариев и импортов (Python через stdlib `ast`, остальные 16 языков Tier B через опциональный `tree-sitter-language-pack` + `ts_ast.py`, прочее как Tier D узлы), разрешение импортов в граф зависимостей (`MAP_VERSION = 2`) и сохранение карты в `.code-reviewer/map.json`. Если в git уже есть коммиты и `last_reviewed_commit` пуст — фиксирует первый `HEAD`.
   - Опциональный режим `init --ai-summary` генерирует краткие описания модулей по их сигнатурам и docstring, кэшируя их в `.code-reviewer/summary-cache/`. Без этого флага `init` никогда не обращается к LLM.
2. **`check` (ревью diff через LLM):** сбор diff (`auto`, `staged`, `unstaged`, `--last`, `--since-last`, `--commit`, `--range`, а также `--all` по всей карте с `-p/--path`, `--no-tests` и защитой квоты), маскирование секретов, разбиение на чанки по связным компонентам графа зависимостей, сбор контекста из карты, вызов OpenAI-совместимого API, разбор JSON-ответа, фильтрация галлюцинаций и ignore-директив, вывод отчёта (`table` / `json` / `md` / `sarif`) и запись в историю.

## Технологический стек

- **Python:** `>=3.12` (целевая версия разработки — **3.14**, управление через `uv`).
- **CLI:** `typer` (команды `code-reviewer` и короткий алиас `cr`).
- **Терминальный вывод:** `rich`.
- **HTTP-клиент к LLM:** `httpx` (OpenAI-совместимый API `/chat/completions`).
- **Конфигурация и валидация:** `tomllib` (stdlib) + `pydantic` v2.
- **Парсинг кода:** stdlib `ast` (Tier A: Python), опциональный `tree-sitter` + `tree-sitter-language-pack` (Tier B: JS/TS/TSX, Go, Rust, Java, Kotlin, C/C++, C#, Ruby, PHP, Swift, Lua, Dart, Scala), `PlainAdapter` (Tier D: всё остальное).
- **Тесты и качество кода:** `pytest`, `ruff`, `mypy`.

## Структура проекта

```text
src/code_reviewer/
├── __init__.py           # версия пакета
├── __main__.py           # запуск через python -m code_reviewer
├── core/                 # базовые модели, конфиг, ошибки, glob-матчинг, атомарное хранилище
├── vcs/                  # обёртка над git CLI, сбор/разбор diff, git pre-commit хук
├── indexing/             # discovery, парсеры (python_ast, treesitter, ts_ast, plain), resolver, граф, builder, AI-сводки
├── llm/                  # протокол клиента, потокобезопасный пул ключей (keys.txt), OpenAI-совместимый HTTP-клиент
├── review/               # маскирование секретов, scan (--all), чанкинг, контекст, промпт, разбор находок, ignore, история, пайплайн
├── workflows/            # офлайн-демо, eval-стенд, диагностика окружения (doctor)
├── render/               # вывод в Rich-консоль, JSON, Markdown, SARIF 2.1.0
└── cli/                  # тонкий слой Typer-команд (init, status, check, map, keys, eval, demo, config, doctor, ...)
tests/                    # автотесты pytest
evals/                    # JSON-кейсы для оценки precision / recall / F1
docs/                     # справочник CLI и дополнительная документация
```

Правило зависимостей: `cli/` → `workflows/`, `review/`, `indexing/`, `render/` → `vcs/` → `core/`. Циклические импорты между слоями запрещены.

## Ненарушимые инженерные инварианты

1. **Версия схемы карты (`MAP_VERSION` в `core/models.py`):** обязательно увеличивать при любом изменении логики парсинга, извлечения символов/импортов или формата `map.json`, чтобы инкрементальная сборка пересобирала файлы.
2. **Стабильный ID находки:** `sha256(f"{file}:{line}:{message}")[:8]`. На нём строятся дедупликация, `baseline`, `--verify` и метрики истории.
3. **Строгий порядок фильтрации находок:** `filter_to_paths` (отсев файлов вне diff и приведение пути к каноническому с пересчётом ID) → `ignore` (`.code-reviewerignore` и inline-директивы по полному тексту файла) → `baseline`.
4. **Отсутствие тихого отбрасывания файлов:** всё, что не поместилось в лимит `max_files` или `max_chunks`, попадает в `omitted` и явно отражается в отчёте и промпте.
5. **Детерминированный ключ кэша ответов:** `sha256(model, system, user)`. Не включать временные метки и пути временных директорий.
6. **Коды возврата CLI:**
   - `0` — успешно / замечаний ниже порога `fail_on`;
   - `1` — найдены замечания `>= output.fail_on`, провален `eval --fail-under` или `doctor` обнаружил `FAIL`;
   - `2` — ошибка использования CLI, конфигурации, git, карты или LLM API.
7. **Безопасная Rich-разметка:** любой пользовательский текст (пути, ветки, сигнатуры, docstring, сообщения, поисковые запросы) перед передачей в `rich` обязательно экранировать через `escape()` / `_s()`.
8. **`if TYPE_CHECKING:` в Python:** импорты внутри этого блока намеренно исключаются из графа зависимостей, чтобы не создавать ложных циклов.
9. **Безопасность git-хуков:** чужой `.git/hooks/pre-commit` без флага `--force` не перезаписывается и не удаляется.
10. **Безопасность ключей API:** ключи хранятся в `.code-reviewer/keys.txt` (в `.gitignore`) или в env; значения ключей никогда не печатаются в консоль, логи и `doctor`. Пул ключей (`KeyPool`) потокобезопасен под `threading.Lock`.
11. **Строгий офлайн-режим грамматик:** при `map.fetch_grammars = false` код никогда не пытается скачивать грамматики tree-sitter из сети (при отсутствии локальной грамматики файл деградирует до `PlainAdapter`).
12. **Атомарная запись состояния:** `map.json`, `state.json`, `baseline.json`, `last-review.json`, файлы кэша пишутся через временный файл в той же директории и `os.replace`.
13. **`init` без `--ai-summary` не обращается к LLM.**

## Команды разработки и проверки

```bash
export PATH="$HOME/.local/bin:$PATH"   # uv установлен в ~/.local/bin
uv sync --all-extras                  # установка зависимостей и dev/treesitter/build extras
uv run pytest                         # запуск всех тестов
uv run ruff check src tests scripts   # линтинг
uv run mypy src                       # проверка типов
uv run code-reviewer demo             # проверка пайплайна без сети и API-ключа
```
